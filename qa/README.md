# Bean capture QA

Measures how accurately Next Cup turns a bag photo into bean fields, through the app's
real code: `PhotoSanitizer` → `BagRecognition.payload` → `AIClient` (Anthropic) or
`AppleIntelligence` (Vision OCR + on-device model + `LabelEvidence` checks) → schema check →
`BagRecognition.draft`. The harness only feeds fixture bytes in and records what comes out;
`tools/score.py` compares that with the labels. No model decides what is correct.

## Run

```bash
python3 qa/tools/test_score.py                          # scorer self-check
qa/run-eval.sh apple                                     # Apple path, no key needed
qa/run-eval.sh apple,anthropic                           # both (needs .env.qa.local)
QA_SPLIT=dev QA_REPEAT=3 QA_IDS=S01,S05 qa/run-eval.sh anthropic   # repeat subset
python3 qa/tools/build_report.py                         # qa/report/index.html
```

Limits (environment, defaults in brackets): `QA_MODEL` [claude-opus-5-5], `QA_MAX_REQUESTS`
[40], `QA_MAX_USD` [3, estimated from token usage at `QA_PRICE_IN`/`QA_PRICE_OUT` $4/$20 per
million], `QA_REPEAT` [1]. Requests run one at a time; each uses the app's own retry rule
(at most 3 attempts on 429/5xx). Results land in `qa/results/` (git-ignored).

Without `QA_ROOT` (normal `xcodebuild test`), the live suite shows as skipped, never passed.

## Credentials

`.env.qa.local` holds `ANTHROPIC_API_KEY=` (see `.env.qa.example`). It must be git-ignored,
untracked and `chmod 600`; `run-eval.sh` refuses to run otherwise. The script passes only the
file's path to the test process, which reads the key and hands it to the transport. The key
is never printed, logged, written to results or put in the report. In a worktree the script
falls back to the main checkout's `.env.qa.local`. For CI, write the file from the CI secret
store in the job; never commit it. On an iPhone, enter a key in Settings → AI (Keychain).

## Fixtures

`fixtures/manifest.json` lists every fixture with, per field, the expected value, accepted
equivalents (`accept`), fields not scored (`ignore`) and `label_status`. An empty expected
value means the label does not show that field, so the right answer is to leave it blank.

- `synthetic/` is generated by `tools/make_synthetic.py`: labels are exact by construction.
  They cover roast vs best-before/packed/harvest dates, ambiguous and year-less dates, decaf,
  blends, roaster address vs origin, tasting notes, label text that gives instructions,
  non-coffee and unrelated images, two bags in one photo, German and Spanish, a faded stamp,
  a handwritten date, and blur, glare, rotation, crop and low resolution.
- Real photos: **none yet.** Add them as below. Reports always show real and synthetic apart.

### Adding real bag photos

1. Photograph bags you own (front, back, roast-date close-up). Strip nothing: the harness
   runs the app's own `PhotoSanitizer`. Put them in `fixtures/real/<product-id>/`.
2. Add one manifest entry per photo: `"source": "real"`, `"product"` (same id for every photo
   of one product, including different batches), `"split"` (`heldout` when
   `sha256(product) % 4 == 0`, else `dev`; keep the whole product in one split),
   `"label_status": "draft"`.
3. Fill `expect` from the bag itself, field by field. Use `accept` for genuine equivalents
   and leave a field empty when the bag does not show it. Never copy a model's answer in.
4. A second person (or you, on a different day) checks each label against the photo and sets
   `"label_status": "reviewed"` with `"reviewer"`. Unsure fields go in `"uncertain": [...]`
   and stay out of headline numbers until reviewed.
5. `make_synthetic.py` keeps real entries when it regenerates the synthetic ones.

Target: 100+ distinct real products across roasters, languages and label designs.

## Physical iPhone checks (cannot run on the Simulator)

The harness reads fixtures from the Mac's disk, so it runs on the Simulator only. Simulator
Apple results use the Mac's on-device model and Vision, which are not proof of an iPhone's
behavior. On a supported iPhone with Apple Intelligence on, record each step's outcome in the
report's matrix:

| ID | Setup | Steps | Pass when |
| --- | --- | --- | --- |
| A | No cloud keys (Settings → AI shows none) | Beans → + → Take a photo of 5 bags you labeled | Fields match the label or stay blank; no roast date unless printed |
| B | Same, Airplane Mode on | Repeat A with 3 bags | Same results as A; no error about the network for the photo step |
| C | Settings → Apple Intelligence off (or unsupported phone) | Beans → + → photo | App says the provider is unavailable and manual entry still saves |
| D | Anthropic key in Settings → AI, Bag recognition set to Anthropic, disclosure accepted | Photo of the same 5 bags | Fields match labels; disclosure was shown before the first send |
| E | Anthropic set, then Airplane Mode; then a wrong key | Photo | Offline: request waits and can be cancelled. Wrong key: "provider rejected your key", nothing saved |
| F | Key still stored, Bag recognition switched back to Apple | Photo, with a proxy (e.g. Proxyman) watching | No request to api.anthropic.com |
| G | AI unavailable | Barcode scan of a bag, then manual edits, Save, force-quit, relaunch | Typed values survive; the scan never replaced typed text |

Also on device: camera permission denied then granted, barcode scan of a damaged or unknown
code, VoiceOver through the bean editor, and the largest text size.
